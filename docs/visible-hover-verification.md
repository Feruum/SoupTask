# Visible source values — 11 November 2026

Earlier hover results established source DOM commit plus two animation-frame callbacks. They did **not** establish that the source table was on screen: the old Compare table was below the900px viewport. Those historical numbers remain available, but must not be used as evidence of readable on-screen source values.

## Corrected interface and acceptance

At desktop widths of at least1100px and heights of at least700px, the common readout occupies a permanent bottom area. The main content scrolls in the remaining space; the readout does not cover the chart input surface. Narrow/short screens retain the in-flow, keyboard-scrollable table. Geometry, numeric font treatment and border radius remain constant when values appear.

The current frame acknowledgement still requires the current workspace/view/hover identity, committed original source values and **two RAF callbacks**. At the second callback, read-only validation checks the full text bounds of the first source observation's actual step and all three metrics for each run, or the explicit missing-observation message. Bounds must fit the viewport and every applicable clipping ancestor. A center hit test samples occlusion for each cell. The standard performance harness independently rechecks the actual cells. The check does not claim every physical pixel is unobscured; opaque pointer-events:none overlays and unsupported transformed fixed-position ancestors require additional review. Duplicate-group rows remain available through table scrolling and source links; the timing endpoint does not require every duplicate row to fit simultaneously.

Browser regressions demonstrate the original offscreen failure, valid visible values, and rejection of deliberately offscreen, clipped or covered values. Existing hover-layout checks account for ancestor scroll offsets rather than mistaking intentional scrolling for layout shift. The desktop captures show all16 actual step/metric cells in a four-run comparison. Mobile layout and keyboard/source actions are checked separately; desktop timing is not a mobile performance claim.

## Measurement changes and rejected result

The revised harness retains30 range-form-to-chart-entry interactions for details and30 for Compare, and adds separate30-sample continuous movement series after two warmups. It does not substitute the faster interaction class for the original entry scenario. Two RAFs are retained. New visible-value results must not be compared numerically as if the previous offscreen endpoint were equivalent.

The first correct-visibility implementation sampled five hit-test locations per cell. [Its full trace](../reports/memory-investigation-2026-11-10/visible-hover-trace1/results.json) failed latency budgets: detail/Compare entry p95 was63.9/102.4ms. Some second-RAF callbacks contained80HitTests and lasted54ms; HitTest events alone summed about18–19ms. This is observer work introduced by the validator, not evidence that raw lookup became slow. Per-frame computed-property/ancestor-visibility caching and one cell-center sample reduced that overhead, while retaining full text-bound clipping checks and including verification time before the frame mark.

[The next full run](../reports/memory-investigation-2026-11-10/visible-hover-trace2/results.json) records detail/Compare entry57.5/70.0ms; continuous movement45.4/79.5ms; cold2859.4ms; detail/Compare zoom138.7/164.8ms. These are one-run results, not a stable≤50ms claim. All raw samples and slower attempts remain retained.

## Exact invalidation diagnosis

[Extra diagnostic invalidation/stack recording](../reports/memory-investigation-2026-11-10/hover-invalidation-before/results.json) is a distinct30-entry experiment, not the standard acceptance trace mode. Its [phase analysis](../reports/memory-investigation-2026-11-10/hover-invalidation-before/phase-analysis.json) now includes actual setter stacks. Text replacement in the shared source adapter causes removal/insertion of text layout nodes and schedules BODY `:has` invalidation. In the slowest diagnostic window, UpdateLayoutTree sums17.9ms, Paint15.0ms and Layout10.4ms; these different phase totals must not be added blindly because trace event types can nest.

The isolated fix mutates the existing Text node when a leaf value changes, preserving the unchanged-row suppression already present. [The real failing regression](../reports/memory-investigation-2026-11-10/text-leaf-red/results.json) confirms the original setter replaced that node; [19 checks pass after the fix](../reports/memory-investigation-2026-11-10/text-leaf-green/results.json). The [repeat diagnostic](../reports/memory-investigation-2026-11-10/hover-invalidation-text-leaf/phase-analysis.json) contains no BODY `:has` schedules in its five slowest hover windows, versus29 in the original worst window. Whole diagnostic trace counts fall from629 to84; schedules are not the same as actual style passes. The [standard full run](../reports/memory-investigation-2026-11-10/visible-hover-trace3/results.json) reports detail/Compare entry51.7/55.2ms. This is a useful one-run result, still above50ms, not a randomized causal estimate.

The remaining document-root Layout has a concrete source: native uPlot cursor x/y nodes are added to layout on entry after its default `display:none` hiding. The next isolated adapter CSS override retains their absolute layout geometry and uses `visibility:hidden` while `.u-off` applies. It preserves native crosshair positioning, drag and selection. [A real failing check](../reports/memory-investigation-2026-11-10/cursor-geometry-red/results.json) demonstrates the original layout removal; [20 checks pass with the scoped override](../reports/memory-investigation-2026-11-10/cursor-geometry-green/results.json). These checks establish DOM/CSS behavior, not GPU layer allocation or a performance gain by themselves.

The global BODY relational selectors were replaced with explicit classes owned by the active shared readout. Membership changes update the mode; cleanup restores the shell and scroll area. [The new diagnostic](../reports/memory-investigation-2026-11-10/hover-invalidation-layout-owner/phase-analysis.json) records zero BODY `:has` schedules. Native style visibility checks retain manual full text bounds, ancestor clipping and cell-center hit tests, with a computed-style fallback. Real faults cover offscreen, clipped, covered, hidden and transparent values.

RAF-batched DOM writes did not consistently improve the entry scenario. The selected adapter coalesces at the microtask checkpoint while retaining both post-commit frame checks and displayed-row Pin identity. [Trace8](../reports/memory-investigation-2026-11-10/visible-hover-trace8/results.json) reported Compare entry52.3 ms. An attempted client-box shortcut [did not improve the measured result](../reports/memory-investigation-2026-11-10/visible-hover-trace9/results.json) and was reverted. A tighter row-density experiment was stopped before implementation. Its failed exploratory height check is not part of final acceptance.

The [final same-source results](performance-results.md) use the worse p95 of two complete full recordings, retain separate no-trace and continuous-movement results, and report the actual remaining misses. The release ships the verified demonstration and records the expanded target miss rather than claiming stable sub-50 ms latency.
